## 实际操作和规则

| 操作 | 目的及实现 |
| --- | --- |
| 增加正文事实核验 | 读取明确的成交结果、最终报价和主要标的表；保留表行证据，要求明确货币单位，区分最终报价、评审价格和费率。正文缺失行可以补回，无法唯一归包时不写入 |
| 金额冲突保留候选 | 合并来源遇到不一致的成交金额或投标报价时，保存候选并留空；同一正文存在冲突报价时也不按行顺序选择。明确且唯一的正文事实才能解除冲突 |
| 收紧总金额修正规则 | 平台概况中的 0 和按元取整的金额，不能覆盖成交正文中更精确的值；不会用明细求和推测原文未披露的总额 |
| 区分附件角色 | 独立声明、历史业绩和专家劳务表不构成本次商品或投标事实。混合报价、评审材料和解析不完整的文件保持可核验，防止整份误排除 |
| 匿名投标编号隔离 | 编号来源记录仍保留，企业身份标记为未确认，排除真实企业名录及有效共同竞标统计；23 条编号记录中可计入关系的数量为 0 |
| 跨来源金额保护 | 保留未确认关系的同名商品及原文价格，对涉及的品牌金额显示“待核对”。不能证明重复时不直接删行，也不把两份来源价格自动累加 |
| 更新两条抽取路径和持久化 | 普通及优化抽取都执行来源核验；流水线版本为 `package-v2.14`。SQLite 增加来源引用和确认状态字段；旧快照、旧表行导出均兼容来源引用 |
| 生成可追溯修复副本 | 离线脚本验证输入哈希、限定数据集，支持续作及指定公告复核；输出逐篇审计、隔离记录、全量 JSONL 和标准三表，保留来源文件 SHA-256 |
| 修复双节点图形 | 实际截图发现两个横向节点时画布空白；显式限制画布边界并保持长宽比例，避免图形被放大到画布外或拉伸成条形 |
