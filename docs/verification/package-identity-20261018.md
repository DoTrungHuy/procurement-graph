## 代码与操作

| 操作 | 用途与实际结果 |
| --- | --- |
| 新增 `app/package_identity.py` | 普通和优化抽取完成后检查全篇已解析来源。只接受同项目的明确中标包号与唯一供应商关系，或直接披露且无冲突的单包数量；同价、同供应商和缺少包名本身都不能证明同包 |
| 检查已有编号包 | 同一供应商已经关联多个编号包时，即使当前附件只显示其中一包，也不自动把匿名片段塞进该包 |
| 更新两条抽取路径 | 在全部来源合并后执行包归属核验；更新流水线版本到 `package-v2.13`，不重用旧版本的片段检查点 |
| 新增离线修复工具 | 只创建新数据库副本，校验快照、原附件及摘录；原文变更即拒绝套用复核方案，不调用模型 |
| 生成完整交付副本 | 包含修复库、全量预测、标准三表、修复前10篇快照、逐篇审计及 HTTP 验证结果 |

自动核验与本次逐篇复核不是同一种覆盖范围。现有原文能直接触发自动核验的样本包括教育运维公告和明确写有单包数量的物流实训公告；其余需依照完整原文复核清单处理，不宣称自动算法已经普遍识别全部复杂包结构。
