# 模型服务配置

如果还不熟悉整个项目，先看[新手操作指南](user-guide.md)。本页补充模型配置的保存位置和部署细节。

打开页面左下角的“连接设置”，在“模型服务”中填写服务地址、模型名称和API Key，勾选“启用模型抽取”，点击“保存模型配置”。保存不请求模型；新提交的抽取任务使用新配置，无需重启后端。已经运行的任务继续使用开始时的配置。

服务地址填写兼容OpenAI接口的基础地址，例如 `https://api.deepseek.com` 或服务商指定的 `/v1` 地址；粘贴以 `/chat/completions` 结尾的完整地址时，会自动去掉该后缀。模型名称使用服务商提供的实际标识。

保存后重新打开页面、换浏览器或重启服务，都能读取已保存的地址、模型名称和Key配置状态。Key输入框始终为空，留空保存会保留已有Key，填写新Key会替换。未在页面保存过时，读取原有 `.env` 配置；第一次保存也可以直接保留原有Key。

“服务访问令牌”用于连接受保护的系统，与模型Key不同。远程部署应先在服务端配置 `APP_API_TOKEN`，在页面填写该访问令牌并点击“保存并连接”，再管理模型配置。当前系统使用共享访问令牌，持有该令牌的人可以修改模型设置。

## 保存位置

本地启动默认保存到项目根目录下的 `config/model-settings.local.json`；可用环境变量 `MODEL_SETTINGS_PATH` 指定其他可写路径。Docker Compose保存到 `/app/data/model-settings.local.json`，由业务数据卷持久保存。前端保存的四项配置优先于 `.env` 中对应值；其他部署参数仍由 `.env` 配置。

该文件包含可用Key，应与 `.env` 一样保密。文件采用临时写入后替换，保存失败保留原配置；配置损坏时会暂停新模型调用并提示重新填写。Key不返回浏览器，不写入浏览器的localStorage或sessionStorage。

`.gitignore` 已排除模型私有配置及写入临时文件。GitHub仓库和源码包不携带这些凭据；换电脑克隆项目后需要重新填写，或单独安全迁移私有配置。要保留原设置，备份时应同时保留 `.env` 和此文件。

## 使用边界

保存成功表示配置已写入并可供新任务使用，不代表服务商连接或余额已通过验证。只有提交模型抽取任务才会请求推理服务，并可能产生费用。浏览已有结果、解析预检、历史响应回放不需要新模型请求。

## 强制流式网关

模型调用层同时接受完整 JSON 和 `text/event-stream` 响应，可复用本机 WorkBuddy/DSH 网关；服务地址、模型标识和登录状态以本机实际配置为准。SSE 文本会聚合为原有响应格式，继续使用相同字段校验、入库和缓存流程。缺少完成事件的断流会失败重试，不写入成功响应缓存。

回环地址 `127.0.0.1`、`localhost`、`::1` 的模型请求不继承系统代理，避免本地网关请求被转送至外部代理；其他服务地址沿用原有代理行为。

WorkBuddy DS4.1 偶尔会在 JSON 字符串之外返回 `<|endoftext|>` 控制标记。兼容层只移除此处的标记，字符串中的原文照录；发生清理时，响应缓存同时保留原始文本和清理次数，便于核查。

临时免费批处理可通过进程环境设置 `MODEL_REQUIRE_FREE=true`：每个新响应须由上游 `usage.credit` 明确报告为零，否则停止该批次后续模型请求。此开关默认关闭，原有直连服务配置继续可用。免费标价须在运行前核对；此检查发生在响应之后，不能保证活动变价后的首个请求不扣积分，也不代表永久免费。批处理可使用 `python -m app.batch --database ... --output ... --mode extract --run-model` 隔离数据库和结果，不覆盖已有数据。
